# Engineering Manager

## Brief checklist

Give each Worker a bounded brief and size it for one context where possible. Split a long inventory by file group and follow the [ladder's assignment guidance](worker-ladder.md#shape-and-run-assignments). Carry authority from actual user sources. Native tool responses establish launch and status. Worker summaries are evidence to inspect. Use native task records without requiring a task directory, immutable JSON contract, or fixed response schema.

- Role and dispatch title. Worker or reviewer, no nested agents. Set the dispatch title to `<verb> #n [rN] · <tier>` or `<verb> <object> · <tier>`. Omit an absent issue number and omit the review or rework round `rN` on the first pass.
- Objective, original requirements, and amendments.
- Worktree and named paths.
- Authorized actions and user sources for edit, commit, push, and PR.
- Acceptance criteria and named output files.
- Tier and reason.
- Timeout in seconds, sized to the task up to the tier’s `timeout_s` ceiling.
- Host and repository limits. Follow `host-ops` and carry current rules and telemetry paths into delegations and resumes. Include applicable CI-only limits on local builds, tests, and typechecks.
- Formatter evidence, if a gate applies. Require the command and quoted exit code, e.g. `cargo fmt --all -- --check; echo exit=$?`. Reject gate claims without this evidence. Repository hooks generated by dev-skills change upstream, without hand edits in a repository.
- PR delivery. Supply the [PR CI trigger procedure](pr-ci-trigger.md) inline or at its resolved installed path (normally `~/.agents/skills/orchestrate-harnesses/references/pr-ci-trigger.md`). A generated prompt cannot rely on relative resource links. Record recovery authority and remaining pushes in the round. Have Workers report `PR <url>, head <sha>, checks <state>` and keep them responsible for branch fixes through exact-head green CI within that allowance.

## Reduce Manager calls

- When a watched PR check fails, resume the branch's Worker or dispatch an L1 Worker with the run URL to triage. Leave fetching and searching failed logs to that Worker.
- Delegate diff review to an independent L1/L2 reviewer. Supply the PR and requirements. Read its terse findings and the Worker report, then inspect only hunks that change a contract, such as config schema, public docs, persisted formats or hook policy.
- Verify CI once on the exact head before merging.
- Batch independent Manager checks into one tool call. Avoid exploratory one-liners.
- Keep web page bodies out of Manager context, including WebFetch, `curl` or `wget`, `gh api` HTML, and preview DOM or snapshot dumps. Send a fast Worker the question and URLs for a short answer with links. WebSearch result lists and browser work the user asks the Manager to do are fine.

## Verify delivery

Inspect actual artifacts, changed paths and revisions, verification, unresolved findings and limits. Check all original requirements and amendments, every item in a list-shaped deliverable, and required CI tied to the revision. Verify authorized remote delivery against the actual remote branch and SHA. Report failed pushes and the exact unpushed state. WIP handover requires push authority. Pause or cancellation grants no authority for more work.

A Worker cannot accept its own work. Give the verdict in this Manager session. Missing evidence means more work or a precise blocker. Read-only tasks may need no Worker or commit.

## Design and stuck checkpoints

Prefer the simplest design that meets the stated requirements. Before adopting any design, contract or plan, trace each mechanism (lock, retry, recovery path, extra state, format field or delivery guarantee) to a user requirement or stated threat. Say what the design deliberately leaves out. Drop an untraceable mechanism or ask the user before adopting it. Bring costly-to-reverse choices to the user early with options and a recommendation using `prompt-for-decisions`. Manager or reviewer acceptance cannot settle the choice.

You are stuck when any of these happens:

- two consecutive review rounds find the same kind of defect, such as further lock or recovery interactions;
- a task reaches `max_auto_rework`;
- a PR or contract grows to about twice the size the plan or request implied;
- Workers keep ending early on the same work after a tier change.

At a trigger, stop dispatching fixes. Check which requirement forces each part of the complexity and what a simpler design would drop. If an independent view would help, give an L2 Worker a short, neutral design audit of the user's requirements and the design, excluding your hypothesis. Use `prompt-for-decisions` to give the user a short summary, options including simplification or narrowing the scope, and your recommendation. Hold further fixes on that work until the user answers. Continue independent work.

## Worker lifecycle

If a Worker returns early without a concrete blocker, resume it once in the same context. This does not count against `policy.max_auto_rework`. A second early stop at that tier counts as a failed attempt and may justify the next tier. A concrete blocker the next tier could resolve also justifies escalation. Record the reason and apply the stuck checkpoints if early stops continue after changing tiers.
