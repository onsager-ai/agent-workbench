# Automation policy

Before enabling recurring, unattended, or externally triggered work, a Manager registers it in the personal inventory at `~/.agents/skills/workbench-personal/automations.yml`, using [automations.schema.json](automations.schema.json), then enables it in the same turn. Workers never create or enable automations. Infra reconciles the inventory against active automation. Bind each entry to a host, project, configured model, schedule, cost cap, and end condition. L1/L2 are the default; Opus requires an owner L3 approval line. Money, public actions, and credential use each need their own approval.

This policy covers T3 schedules, `/loop` and current-thread wakeups, system cron/systemd jobs, PR watches, daemons, and unattended threads. Manager follow-ups use the current session where supported. Create a new top-level thread only on the owner's explicit request. When a dedicated scheduled thread completes its work, it reports the result to its owner lane and settles itself; it never settles an ongoing Manager thread after a wakeup.

The hook denies new T3 schedule creation because that schema cannot select a model; only a pause-only update to an identified schedule is allowed. List/read, delete, and cleanup remain available. It enforces Worker denials for observable thread, watch, and local wakeup calls, validates new PR watches against a repository/PR, URL, or explicit thread ID, and validates thread creation against each tool's explicit environment, project, and configured L1/L2 model fields. It normalizes T3 tool names across Claude and Codex spellings. Codex lacks reliable standalone Manager/Worker role metadata, so top-level thread creation, new PR watches, and recognized shell-based automation creation fail closed there; ordinary delegation and already-running watches remain unaffected. For other Codex automation tools without role metadata, lifecycle rules remain instructions so ordinary non-LLM jobs are not blocked. Hooks cannot prove owner intent, inspect arbitrary service scripts, or infer schedule, cost, and end behavior from shell commands. Infra reconciles the canonical inventory.
