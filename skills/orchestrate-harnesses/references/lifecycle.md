# Controller lifecycle decision

One task has one short-held file lock. The lock serializes state updates and the actual process start; it is not held while waiting for inference. A pause/cancel transaction therefore either precedes launch and prevents it, or follows the registered child launch and requests its stop. A second execution while `active` is present fails. State writes use a same-directory temporary file, fsync and rename. Original payload files are immutable; messages and dispatch requests are idempotent by ID and content.

`ready -> running -> ready/blocked/accepted`; `pause` sets `paused` before stopping; `resume` clears only a settled pause and never starts a child; `cancel` is terminal and blocks all further dispatch. The controller polls stop state at intervals of at most 0.1 seconds, terminates its own process group, waits a bounded grace period, then kills that group if necessary. It records actual termination before clearing `active`. A remote action already committed cannot be undone by cancellation. This is stop-and-resume steering, not live streaming into an unrelated process.

A run is `submitted` when its process starts, and messages become `acknowledged` only after validated JSON returns the exact task ID and all input message IDs. Timeout, invalid output, budget exhaustion and CLI errors remain uncertain/failed, never acknowledged success. Retry uses a new explicit request ID after inspecting partial edits. Reusing a completed request ID returns its record without model invocation. There is no automatic retry loop.

Recovery is explicit. Check boot ID plus both controller and child Linux process start times before signaling anything; never trust a recycled PID. A live controller cannot be recovered. An orphan with a verified start time may be stopped; ambiguous identity blocks recovery. Recovering clears a stale active lease only after the owned child is gone, records uncertainty and does not execute anything. Task-owned native session IDs may resume only in the same role and model; default reconstruction uses originals plus compact task results. Reviewers are always fresh. No `--last`, tmux typing, credential reading, permission expansion, new daemon or cross-machine action.

The environment role guard prevents accidental nested controller use, not hostile same-user processes. Filesystem permissions and native CLI policies remain the real execution boundaries. External side effects are at-least-once/uncertain on crash, not exactly-once. Gateway verifies repository state and CI before final delivery.

Intake file SHA256 values bind the original, raw contract and message payload copies. Per-recipient submission status is separate from irrevocable acknowledgement history; aggregate delivery is partial until every declared recipient acknowledges. Optional reviewers are never launched merely to fill the aggregate. `recover --abandon` terminates the task state, preserves possible-orphan evidence and blocks further dispatch without claiming process termination. Group liveness uses kernel checks and bounded owned-process metadata; unresolved orphan/zombie groups fail closed, without a /proc corpus scan.

Worker startup adds an owned `probe` phase before the existing `model` phase. Both launches and PID/start/boot registration occur under the task lock, and all waits release it. The probe uses the same identity-checked process-group termination as inference; cancellation and recovery retain an uncertain lease if termination cannot be verified. A stopped probe records `probe-complete` before transitioning, and launch rechecks stop state and immutable inputs. Recovery/abandon of either probe phase never increments Worker inference/rework counters. A crash in the actual model launch phase retains conservative accounting. Append-only `probe-audit.jsonl` records are private task state, not public source or proof of all permission boundaries.
