# Continue existing engineering work

Keep the user's desired result, authority, unresolved requests, and links to relevant tasks. Reuse issue/PR and task records. When several tasks matter, keep their IDs, dependencies, and next actions. A simple edit needs no orchestration record. Answer unrelated factual questions on their own. Read only the historical ruling relevant to a specific cited hold.

## Follow-ups

- Identify which task or object the user means. Preserve the original objective and unresolved amendments. Explicit cancellations or replacements change the scope. Ask only if ambiguity changes the next action.
- Answer status from the task's native status, Worker reports, and verified repository/CI evidence, distinguishing the three. A status request alone needs no new task, dispatch, review or queued amendment and does not change requirements.
- Keep original user sources for amendments. Send changed requirements through supported native messaging and confirm affected Workers read material changes. A queued message is not acknowledgement. If live steering is unavailable, settle the owned run before redispatch. Recheck the brief and review against the amendments.
- Scope or permission expansion needs actual user authority and an updated linked brief that preserves the original sources. Reconcile or stop affected work before starting the expanded work or replaying an action.
- Apply stop requests to the task and affected Workers through native controls. Confirm what actually stopped, report uncertain work, and reconcile partial effects before resuming. A stop does not undo edits or external actions already made.

## Next action

Continue useful, authorized work. Return defects or changed requirements in an updated brief. Preserve explicit holds and reuse settled answers. Use `prompt-for-decisions` only after preparing concrete evidence for a genuinely unresolved choice. See the [Manager checkpoints](manager.md#design-and-stuck-checkpoints) when a rework trigger fires.

Parallelize only independent work that is ready and authorized. There is no standing target for concurrent tasks. Use supported waits or notifications for owned runs and CI. When no useful authorized action remains, name the blocker and what can release it. Avoid busywork, repeated questions and promises of unattended continuation without a live mechanism.

After confirming a task's PR merge, remove its worktree and local branch with `npx -y @onsager/awb prune --apply`. Check the [delivery evidence](manager.md#verify-delivery) before reporting the result. Keep technical acceptance separate from authorization and remote delivery.
